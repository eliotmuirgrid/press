# Fork a repository

At a high level, to **fork a repository** means to create your own personal copy of someone else's project (repository). This allows you to:

- Experiment with changes without affecting the original project.
- Make improvements or fixes.
- Propose those changes back to the original project, usually via a pull request.

**In short:** Forking lets you freely work on your copy of a project, while keeping a connection to the original for collaboration.

Some Git hosting platforms like [Github](./github) make it possible to fork a repository through their user interface but this a core part of GIT itself.

It's one of the reasons [Flow](/flow) technology is based on GIT.  It's important that customers using Flow are able to modify and extend Flow to meet their own unique needs. 

In other words - the [bottleneck](/system/toc/bottleneck) which is holding their business back from growth.
